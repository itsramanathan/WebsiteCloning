## SPEC-6 — low

app/INTEGRATION.md:9

INTEGRATION.md line 9 tells an adapter author to 'use the browser's `demo_session` cookie'. After the CODE-10 repair the server reads and sets `demo_session_<demoId>` (server.js:257-265, 271, 430) and no `demo_session` cookie is issued anywhere. The handoff requires describing the widget seam contract. Trigger: an adapter author implements against the documented cookie name. Consequence: the adapter looks for a cookie that never exists; since the adapter runs in-browser with automatic cookie handling the practical impact is confusion rather than a runtime failure, which is why this is low.

Suggested follow-up: Update INTEGRATION.md to state the cookie is `demo_session_<demoId>` where demoId is the 16-character server-generated id, and that the browser sends it automatically on same-origin requests.

## CODE-13 — low

app/src/builder.js:91-98; app/src/extract.js:345

builder.js:91-93 throws 'The source did not return an HTML page.' for any fetched page before the new off-origin skip at 94-98. selectNextPages (extract.js:345) picks the collection candidate by matching /shop|products?|collections?|catalog|.../ against the URL and label, so an anchor such as `<a href="/catalog.xml">Catalog</a>` or a `/products.pdf` link is selected. Trigger: a homepage with a credible JSON-LD or card catalog whose first matching link returns application/xml or application/pdf. Consequence: the whole attempt fails and the already-captured home catalog is discarded, the same failure class CODE-12 was meant to close. Not a regression from round 3 and bounded by the page cap, so low.

Suggested follow-up: For secondary pages (pages.length > 0), treat a non-HTML content type like the off-origin case: push a capture limitation such as 'A linked page was not an HTML page and was not captured' and continue; keep the throw for the first page. Add a builder test mirroring the off-origin regression.

## CODE-14 — low

app/src/server.js:87-90; app/src/store.js:323,348-350

DELETE calls runner.cancel then store.deleteDemo, which removes `demos/<id>` (store.js:323). If the builder ignores the abort signal (the path test/server.test.js:336-385 exercises), buildAttempt's mkdir recursive recreates `demos/<id>/attempt-N/assets`; late cleanup (server.js:88-89) calls removeAttempt, which removes only the attempt directory (store.js:348-350), leaving an empty `demos/<id>` directory. Trigger: delete during a build whose worker does not honour abort. Consequence: an empty orphan directory per such delete; no data or access impact. The production builder is cooperative (builder.js:12-14,26,50,127,131 plus fetch abort), so this is a hygiene issue only.

Suggested follow-up: In the late-settlement handler, when the demo record is tombstoned, remove `demos/<id>` rather than only the attempt directory, or have removeAttempt prune an empty parent.

## Review limitations

- Static review only. verify.sh, node --test, browser-verify.mjs and live-smoke.mjs were not executed by this reviewer; their results are host-supplied records (ROUND_3_DISPOSITIONS, EVIDENCE.md, live-smoke.json) that were inspected for consistency with source.
- browser-verify.mjs and live-smoke.mjs load Playwright from a machine-specific cache path; verify.sh skips the browser lane when that path is absent, so the browser evidence is not reproducible on another host without PLAYWRIGHT_MODULE.
- Cross-site share entry was verified by the host only in bundled Chromium via localhost to 127.0.0.1; webmail/chat-client initiators, Safari, Firefox and cookie-blocking configurations are unverified.
- Delete focus restoration depends on the deleted card holding focus before the button is disabled; browsers that do not focus buttons on mouse click (for example Safari) will not move focus, and screen-reader announcement behavior was not tested with an assistive technology.
- Visual resemblance is evidenced for one live source (books.toscrape.com) and a deterministic fixture only; screenshots were not viewed as images by this reviewer and do not prove fidelity on arbitrary sites.
- Live widget integration, remote hosting, and model-driven analysis remain unimplemented broader goals, documented as such; nothing here credits them.
- Performance behavior was traced but not measured; the single-process JSON store rewrite per mutation is documented as an accepted local-tool limit.
